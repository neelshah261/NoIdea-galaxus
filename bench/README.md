# `bench/`: the speed matrix (issue #33)

Speed and resources are 20% of the score. This directory holds **one table** that says what we run, how fast, on
what hardware and at what cost — plus the exact commands a human runs to fill the GPU rows of it.

It sits on top of `src/galaxus/serve/bench.py`, which already does the measuring (timing after warm-up, peak
memory, and `cost_per_100k` from [PLAN.md](../PLAN.md) "Speed"). Nothing here re-derives the cost formula.

| File | What |
| --- | --- |
| [`speed_matrix.py`](speed_matrix.py) | the grid, the per-cell runner, the saved record, the markdown table, the CLI |
| [`gpu_plan.py`](gpu_plan.py) | generates the commands below from the grid, so the two cannot drift apart |
| [`fake_backend.py`](fake_backend.py) | a CPU stand-in with no model, so the machinery can be proven without a GPU |

Two rules the code enforces rather than documents:

- **An unrun cell stays empty.** `CellResult` refuses to be built with a number unless its status is `done`, and a
  `done` row must name its hardware and its speed. No cell is ever filled with a plausible figure.
- **Raw results never enter git.** They are appended to `$GALAXUS_DATA/out/bench/<label>.jsonl`
  ([AGENTS.md](../AGENTS.md) product rule 3); `matrix_path` refuses any root inside the repository.

`results/metrics.json` is written only by the model lane's eval script, so this lane proposes a hand-over format in
its PR's "For design" notes and writes nothing into that file.

## The grid

Five axes, exactly as issue #33 asks:

| Axis | Values | Where they come from |
| --- | --- | --- |
| image area | 384, 512, 768 | the ablation in PLAN.md "Speed"; 512 is `galaxus.data.images.IMAGE_SIZE` |
| batch size | 1, 16, 64 | 1 is the latency floor, 16 is `galaxus.serve.runner.DEFAULT_BATCH_SIZE`, 64 is throughput |
| backend | `vllm`, `local` | BASE_ARCHITECTURE.md section 1 (`api` is someone else's hardware, so not a speed cell) |
| precision | `bf16`, `fp8`, `awq-int4`, `gptq-int4` | bf16 is the documented main line; the rest is what #33 asks about |
| prefix caching | on, off | PLAN.md "Speed" turns it on for the shared prompt; off is the ablation |

The full product is **144** cells. **63** of them are `not-applicable` and are left out of the table, each with a
reason the code prints: prefix caching is a vLLM feature, so the transformers backend cannot have it, and a
quantized transformers load would need a new dependency, which a worker never adds (AGENTS.md "Lanes").

That leaves **81** cells, in four run bands:

| Band | Cells | What |
| --- | --- | --- |
| `p0` | 9 | vLLM, bf16, prefix caching on: the documented main line, over all three areas and batch sizes |
| `p1` | 18 | the prefix-caching-off ablation (9) and the transformers backend at bf16 (9) |
| `p2` | 6 | fp8 and int4 at the reference point (512, batch 16), with and without prefix caching |
| `p3` | 48 | the same quantizations over the rest of the area/batch grid |

**27 cells are `supported` and 54 are `unconfirmed`.** Nothing in this repository says the swiss-ai vLLM image
supports fp8 or int4; issue #17 only records that the hosts served bf16 and did not try quantization ("maybe it
works well for Apertus, I don't know"). So those 54 cells are gated behind the probe in Step 2 below rather than
behind a guess.

```bash
uv run python -m bench.speed_matrix grid --format md            # the whole table, every cell empty
uv run python -m bench.speed_matrix grid --format ids --priority p0
```

## What has actually been run

| Rows | Status |
| --- | --- |
| 9 CPU cells (`fake` backend, no model) | **run**: the three image areas x the three batch sizes |
| 27 supported GPU cells (`p0`, `p1`) | **pending** — a human runs the commands below |
| 54 unconfirmed GPU cells (`p2`, `p3`) | **pending**, and gated behind the Step 2 probe |

The CPU rows measure image preparation only (decode, composite onto white, resize, re-encode) and are marked
`is_machinery_check: true`. They prove the harness runs end to end — grid, runner, cost formula, record, output
path, table — and they say nothing about Apertus. They are never reported as vLLM or transformers numbers.

```bash
export GALAXUS_DATA=~/galaxus-data
uv run python -m bench.speed_matrix fake --images 96
```

## The commands for the GPU cells

Generated by `uv run python -m bench.speed_matrix plan`. **Regenerate it rather than editing it here**, and pass
`--priority p2,p3` once Step 2 has answered. An agent must not run any of this: AGENTS.md product rule 7, agents
never start a paid GPU job.

### Step 1 - the data, the hardware, the price

```bash
# 1. The data, outside the repository (AGENTS.md product rule 3).
export GALAXUS_DATA=~/galaxus-data

# 2. Name the hardware. Issue #33 wants it named, not assumed: this string lands in every row.
export GPU_NAME="$(nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,noheader | head -1)"
echo "$GPU_NAME"

# 3. The hourly price of that GPU, and where it comes from. Never invent one; an empty price leaves the
#    $/100k column empty instead of wrong (TODO(owner): read it off the provider's price page before you run).
export GPU_PRICE=            # e.g. 1.80
export GPU_PRICE_SOURCE=     # e.g. "RunPod L40S on-demand, 28 Nov 2026"

# 4. The commit the numbers belong to, for the EXP row.
git rev-parse --short HEAD
```

### Step 2 - what does the image actually support?

```bash
# Run this BEFORE any fp8 / awq-int4 / gptq-int4 cell. Nothing in this repository says the swiss-ai image
# supports them, and issue #17 only records that the hosts served bf16 and did not try quantization.
docker run --rm --gpus all ghcr.io/swiss-ai/vllm_apertus_1.5_release python - <<'PROBE'
import vllm
print("vllm", vllm.__version__)
try:
    from vllm.model_executor.layers.quantization import QUANTIZATION_METHODS
    print("quantization methods:", sorted(QUANTIZATION_METHODS))
except Exception as unavailable:
    print("could not list them here:", type(unavailable).__name__, unavailable)
    print("fall back to: vllm serve --help | grep -A3 -i quantization")
PROBE
```

Paste the answer into the PR. Until it says yes, an fp8 or int4 cell stays empty.

### Step 3 - the vLLM cells (`p0` and the caching ablation of `p1`)

```bash
docker run --rm --gpus all --shm-size 16g \
  -e GALAXUS_DATA=/data -e HF_HOME=/data/hf \
  -e GPU_NAME="$GPU_NAME" -e GPU_PRICE="$GPU_PRICE" -e GPU_PRICE_SOURCE="$GPU_PRICE_SOURCE" \
  -v "$GALAXUS_DATA:/data" -v "$PWD:/repo" -w /repo \
  ghcr.io/swiss-ai/vllm_apertus_1.5_release bash -s <<'IN_CONTAINER'
set -eu
pip install -q -e .
for cell in a384-b1-vllm-bf16-cache_on \
          a384-b16-vllm-bf16-cache_on \
          a384-b64-vllm-bf16-cache_on \
          a512-b1-vllm-bf16-cache_on \
          a512-b16-vllm-bf16-cache_on \
          a512-b64-vllm-bf16-cache_on \
          a768-b1-vllm-bf16-cache_on \
          a768-b16-vllm-bf16-cache_on \
          a768-b64-vllm-bf16-cache_on \
          a384-b1-vllm-bf16-cache_off \
          a384-b16-vllm-bf16-cache_off \
          a384-b64-vllm-bf16-cache_off \
          a512-b1-vllm-bf16-cache_off \
          a512-b16-vllm-bf16-cache_off \
          a512-b64-vllm-bf16-cache_off \
          a768-b1-vllm-bf16-cache_off \
          a768-b16-vllm-bf16-cache_off \
          a768-b64-vllm-bf16-cache_off; do
  python -m bench.speed_matrix run --cell "$cell" \
    --predictor galaxus.model.apertus.vllm:ApertusVllmPredictor \
    --predictor-arg model=swiss-ai/Apertus-v1.5-8B \
    --part dev --limit 256 --warmup 1 \
    --hardware "$GPU_NAME" \
    ${GPU_PRICE:+--dollars-per-hour "$GPU_PRICE"} ${GPU_PRICE:+--price-source "$GPU_PRICE_SOURCE"} \
    --label speed_matrix || echo "cell $cell failed: its row stays empty, not guessed"
done
IN_CONTAINER
```


## The record each run appends

One JSON object per line in `$GALAXUS_DATA/out/bench/<label>.jsonl`. The fields that matter for the report:

| Field | Meaning |
| --- | --- |
| `cell_id`, `image_area`, `batch_size`, `backend`, `precision`, `prefix_caching` | the five axes of the cell |
| `status` | `done`, `pending`, `skipped` or `failed`; everything but `done` has no numbers |
| `support`, `priority`, `note` | why the cell is runnable and when to run it |
| `hardware`, `price_source`, `detected_device` | the hardware as a human named it, and what the driver reported |
| `images`, `warmup_images`, `seconds`, `images_per_second` | the timing, warm-up excluded |
| `peak_memory_gb`, `memory_note` | peak CUDA memory, and what that reading means |
| `dollars_per_hour`, `cost_per_100k`, `hours_per_100k` | the PLAN.md "Speed" cost, empty without a price |
| `vision_tokens_per_image` | from `galaxus.data.images.PATCH_SIZE`; TODO(model): Apertus' own patch size is Q-0002 |
| `is_machinery_check` | true when the row proves the harness, not the product |
| `predictor`, `labels_source`, `part`, `finished_at` | provenance |
